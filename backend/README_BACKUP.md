Backup scheduling
-----------------

When using Docker Compose, schedule the command inside the backend container so it can access PostgreSQL and `pg_dump`. Example (runs at 03:00):

```
0 3 * * * cd /root/kaira_wallet && /usr/bin/docker compose exec -T backend python3 scripts/run_backup_if_needed.py >> /root/kaira_wallet/backend/backup.log 2>&1
```

Notes:
- The script reads `backup_config.json` generated by the API when the user updates the frequency.
- For PostgreSQL the script uses `pg_dump`; it does not create or log a fake backup if that command fails.
- For SQLite it will copy the DB file.
- Ensure the cron environment has the necessary `DATABASE_URL` env var and `pg_dump` in PATH if using Postgres.

Requirements
------------

- `pg_dump` for PostgreSQL backups. Either install PostgreSQL client tools so `pg_dump` is in `PATH`, or set the environment variable `PG_DUMP_PATH` to the full path of the `pg_dump` executable.

Windows

- Install PostgreSQL from https://www.postgresql.org/download/windows/ and ensure the `bin` folder (e.g. `C:\Program Files\PostgreSQL\15\bin`) is in your `PATH`, or set `PG_DUMP_PATH` to `C:\Program Files\PostgreSQL\15\bin\pg_dump.exe`.

Linux (Debian/Ubuntu)

- Install client tools: `sudo apt install postgresql-client`

Testing

- Run the backup script locally (it will report if `pg_dump` is missing):

```bash
python backend/scripts/run_backup_if_needed.py --force
```

Notes
-----

- The script falls back to the `DATABASE_URL` constructed in `backend/database.py` if `DATABASE_URL` is not present in the environment.

Testing and service info
-----------------------

- Backend API (cuando se ejecuta con el Docker Compose del repo) está expuesta en: `http://localhost:8000`.
	- Endpoints relevantes:
		- `GET /api/backup` — obtener frecuencia actual
		- `POST /api/backup` — actualizar frecuencia `{ "frequency_days": 7 }`
		- `POST /api/backup/run` — ejecutar copia de seguridad ahora

- Frontend (cuando se ejecuta en Docker Compose) está disponible en `http://localhost:5174`.

¿Hay que reiniciar Docker?
- Sí: si estás usando Docker Compose y ya tienes los contenedores corriendo, reinicia el servicio `backend` para que cargue los nuevos endpoints y scripts (o reinicia todo):

```bash
docker compose restart backend
```

O para reiniciar ambos contenedores backend y frontend:

```bash
docker compose restart backend frontend
```

Instalar el programador
-----------------------
- Opciones:
	- Usar systemd timer: los archivos están en `backend/deploy/backup.service` y `backend/deploy/backup.timer`. Para activarlos:

```bash
sudo cp backend/deploy/backup.service /etc/systemd/system/
sudo cp backend/deploy/backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now backup.timer
```

	- Usar cron: ejecutar `backend/scripts/install_backup_cron.sh` (añade una entrada de crontab del usuario actual que ejecuta el script a las 03:00 todos los días):

```bash
bash backend/scripts/install_backup_cron.sh
```
